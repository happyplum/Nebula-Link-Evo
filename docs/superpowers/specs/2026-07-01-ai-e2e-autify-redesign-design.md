# AI-E2E Autify 风格重设计

## 1. 背景与目标

当前 `ai-e2e/ui` 是一个功能完整的后台式工具：项目 → 配置 → PRD 分析 → 场景 → 探索 → 脚本 → 执行 → 报告，通过顶部 Tab 切换。每个环节都有数据与 API 支撑，但界面呈现为“工程师控制台”形态，缺少 Autify 类产品中贯穿始终的**引导式工作流、自然语言入口、可视化执行回放**体验。

本设计目标是在不改动 `ai-e2e` 服务端核心流程与硬边界（不直连 AI、不直连 Playwright、不走 `@ai-sdk/*`）的前提下，把前端改造成**更接近 Autify 的 AI 原生 E2E 测试体验**：

- 降低新用户认知成本：从“一堆 Tab”变成“一步接一步的向导”。
- 提供自然语言发令入口：用一句话启动测试分析/生成/执行。
- 强化执行过程的可视化：实时步骤、截图流、失败定位、诊断建议。
- 保留现有底层能力：PRD 分析、URL 绑定、脚本生成、执行、诊断全部复用。

## 2. 范围与分阶段

采用**分阶段交付**，降低一次改动的风险与验证面。

### 阶段 A：UI 重设计与关键页面（MVP）

聚焦信息架构、导航、仪表盘、项目详情页、执行面板，先让界面看起来像/用起来像 Autify，底层仍走现有 API。

- 全局导航：左侧边栏升级为“项目空间 + 最近动态 + 快速入口”。
- 首页：从“项目网格”升级为“工作区仪表盘”，展示最近项目、最近执行、快捷创建。
- 项目页：从“7 个平级 Tab”升级为“向导式步骤条 + 上下文面板”。
- 执行页：新增步骤时间线、实时日志、结果卡片、失败高亮。

### 阶段 B：自然语言 Agent 工作流

在前端增加“AI 助手”入口，把现有后端流程包装成自然语言驱动的会话式任务：

- 用户输入：“帮我测试登录流程”。
- 前端调用现有 `POST /api/projects/:id/analysis` 等接口，按状态机推进。
- 用 SSE 事件渲染 Agent 思考过程、步骤进度、结果摘要。
- 提供“确认/修改/重试”等人机协作点。

### 阶段 C：执行回放与可视化调试

在执行页增加截图流、DOM 高亮、步骤回放、失败帧定格。需要后端补充截图/快照链路，或复用探索阶段已有的 `page_snapshot_json`。

**本次设计文档覆盖阶段 A + B 的交互与信息架构；阶段 C 作为后续扩展保留接口。**

## 3. 设计原则

1. **流程优先于表单**：每个页面都回答“用户现在该做什么”。
2. **渐进披露**：复杂配置默认折叠，主路径保持简洁。
3. **自然语言作为一等入口**：不输 PRD 也能发令，PRD 作为“高级模式”。
4. **实时反馈**：AI 分析、执行过程都用 SSE + 进度/步骤可视化。
5. **一致性**：沿用 Atlas dark AMOLED 主题，不引入新的色彩系统。

## 4. 信息架构

### 4.1 全局结构

```
Layout
├── Sidebar
│   ├── Brand / Workspace
│   ├── 快速入口：新建测试、查看报告
│   ├── 最近项目（5 个）
│   └── 全局状态：AI 运行指示器
├── Main Content
│   ├── /                  HomePage（仪表盘）
│   ├── /project/:id       ProjectPage（向导式工作区）
│   ├── /project/:id/run/:runId   RunDetailPage（执行回放，阶段 C）
│   └── /settings          SettingsPage（未来扩展）
└── StatusBar
    ├── 当前项目 + 状态
    └── 代理/服务健康
```

### 4.2 项目页向导步骤

把现有 7 个 Tab 重新组织为 4 个宏观步骤，每个步骤内部保留细分任务：

| 步骤 | 含义 | 包含原 Tab |
|------|------|-----------|
| 1. 准备 | 项目配置 + 登录脚本 + 起始 URL | config |
| 2. 理解 | PRD 分析 + 模块确认 + 场景设计 | analysis + scenario |
| 3. 探索 | 站点探索 + URL 绑定 | exploration |
| 4. 生成与运行 | 脚本生成 + 执行 + 报告 | scripts + execution + report |

步骤条固定在项目页顶部，用户可自由跳转（不强制线性），但用视觉状态提示推荐下一步。

## 5. 关键页面设计

### 5.1 首页 / 仪表盘

从当前“项目列表”扩展为工作区入口：

- 顶部标题区：欢迎语 + “新建测试”主按钮。
- 快捷操作卡片：
  - 用一句话创建测试（自然语言入口，跳转项目创建 + 自动进入分析）。
  - 查看最近报告。
  - 继续上次项目。
- 最近项目：横向卡片，展示项目名、状态、最近执行结果、更新时间。
- 最近执行：小列表，展示脚本名、状态、耗时、失败数。

### 5.2 项目页 / 向导工作区

#### 顶部区域

- 返回首页 + 项目名称。
- 水平步骤条：准备 → 理解 → 探索 → 生成与运行。
- 当前步骤高亮，已完成步骤带勾选，未完成步骤置灰。
- “AI 助手”悬浮按钮：随时唤起自然语言入口。

#### 准备步骤

- 表单：项目名称、目标 URL、浏览器、并发/超时（折叠）。
- 登录脚本录制器：保持现有功能，但用卡片 + 步骤展示。

#### 理解步骤

- 自然语言输入框（置顶）：“描述你要测试的功能，例如：用户登录后下单”。
- PRD 上传作为“高级模式”折叠在下方。
- 分析进度：步骤条 + 当前阶段 + 百分比。
- 模块树：左侧可折叠，右侧详情面板。
- 场景设计：在模块下新增/编辑场景，preconditions ↔ expected_results 用可视化映射。

#### 探索步骤

- 探索控制面板：开始探索、重置、查看进度。
- URL 绑定视图：左侧已发现 URL 列表，右侧页面预览 + 绑定到模块。
- 未绑定模块警告：用 badge 提示。

#### 生成与运行步骤

- 脚本列表：版本、生成时间、状态。
- 一键生成/运行。
- 执行仪表盘：成功率、最近失败、趋势 mini chart。
- 运行详情：日志、诊断、重试。

### 5.3 自然语言 Agent 入口（AI 助手）

一个全局可唤起的侧边抽屉或底部面板：

- 输入框支持多行、历史记录、快捷指令。
- 消息气泡区：
  - 用户消息：自然语言指令。
  - Agent 消息：步骤说明、结果摘要、需要确认的操作（如“发现 5 个模块，是否继续探索？”）。
- 操作按钮：确认、编辑、重试、取消。
- 技术实现：前端把用户输入映射到现有 API 调用，不新增后端 AI 入口。

示例会话：

```
用户：测试登录流程
Agent：好的，我将分析登录相关的测试场景。
      [分析中...] → 发现 3 个模块
      已找到登录页 URL，是否开始生成脚本？
用户：开始
Agent：[生成中...] → 已生成 2 条脚本
      是否立即执行？
用户：执行
Agent：[执行中...] → 1 通过，1 失败
      失败原因：选择器过时。是否自动诊断？
```

## 6. 执行过程可视化

阶段 A 先实现：

- **执行仪表盘**：最近一次运行的大卡片（状态、耗时、通过/失败数）。
- **步骤时间线**：每个脚本执行的步骤列表，带状态图标、耗时、截图缩略图（如后端提供）。
- **实时进度条**：基于 SSE `execution.progress` 事件。
- **失败高亮**：失败步骤用红色边框/背景，点击展开诊断建议。

阶段 C 再补充：

- 截图流画廊。
- 步骤回放播放器（上一帧/下一帧/播放）。
- DOM 高亮叠加层。

## 7. 组件与路由调整

### 新增页面

- `HomePage`：扩展为仪表盘。
- `ProjectPage`：保留路由，内部改为向导式布局。
- `RunDetailPage`（阶段 C）：`/project/:projectId/run/:runId`。

### 新增/复用组件

- `Stepper`：向导步骤条。
- `AgentChat`：自然语言 Agent 面板。
- `RunTimeline`：执行步骤时间线。
- `MetricCard`：仪表盘指标卡片。
- `PagePreview`：已存在，扩展为绑定视图。
- `ProjectCard`：已存在，扩展展示更多元数据。

### 路由调整

在 `routes.tsx` 中新增 `/project/:projectId/run/:runId`，其余保留。

## 8. 视觉与交互规范

- 沿用 Atlas dark AMOLED tokens：纯黑底、灰度文字、蓝色主操作、语义状态色。
- 卡片作为信息容器，统一使用 `surface-elevated` + 1px border。
- 步骤条使用 `border-status-info` 作为激活态，已完成使用 `status-success`。
- 自然语言输入框使用大号 textarea，placeholder 提示示例。
- 浮动 AI 助手按钮固定在右下角，运行中显示脉冲动画。
- 空状态提供明确行动号召，不放裸列表。

## 9. 数据与 API

本次改动**不新增后端 API**，全部复用现有接口：

- 项目：`/api/projects`
- 分析：`/api/projects/:id/analysis`
- 探索：`/api/projects/:id/exploration`
- 脚本：`/api/projects/:id/scripts`
- 执行：`/api/projects/:id/execution`
- 诊断：`/api/projects/:id/diagnosis`
- SSE：`/api/projects/:id/events`

阶段 C 若需要截图流，将依赖后端新增截图存储/读取接口，不在本次范围内。

## 10. 风险与约束

1. **后端边界**：不能为自然语言入口新增直连 AI 的 API，必须通过 `ProxyAdapterClient`。
2. **状态机**：向导步骤需与后端状态机对齐，避免前端显示步骤与后端状态冲突。
3. **SSE 稳定性**：执行过程可视化重度依赖 SSE，需保留现有重连/状态恢复逻辑。
4. **页面快照缺口**：当前手动 URL 无 `page_snapshot_json`，会影响脚本生成质量，但这是后端数据链路问题，前端只负责提示与引导。
5. **范围控制**：阶段 A 只做界面重构与信息架构，不改动后端；阶段 B 只做前端 Agent 包装；阶段 C 需要后端配合截图链路。

## 11. 验收标准

### 阶段 A

- [ ] 首页展示仪表盘：最近项目、最近执行、快捷创建。
- [ ] 项目页顶部出现 4 步向导条，点击可切换视图。
- [ ] 执行页出现步骤时间线与实时进度。
- [ ] 所有现有功能（PRD 分析、URL 绑定、脚本编辑、执行、报告）仍可正常使用。
- [ ] UI 保持 Atlas 主题，无视觉回归。

### 阶段 B

- [ ] 全局可唤起 AI 助手面板。
- [ ] 用户输入自然语言后，前端按状态机依次调用分析/探索/生成/执行 API。
- [ ] Agent 消息正确展示进度、结果、需要确认的操作。
- [ ] 用户可在关键节点确认、编辑或取消。

### 阶段 C（后续）

- [ ] 执行详情页支持截图流查看。
- [ ] 支持步骤回放播放器。
- [ ] 失败帧可放大并查看诊断建议。
