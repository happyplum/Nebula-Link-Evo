# 测试场景与运行编排契约

> 状态：`pending`。本文定义已经确认的目标语义；当前 ai-e2e 只有功能模块下的 scenario、scenario 级 TypeScript 脚本和简单串行 `run-all`，尚未实现调用图与运行 TODO。

## 1. 四层模型

为了让资产复用、运行恢复和历史追溯互不污染，场景编排拆成四层：

| 层次                 | 生命周期     | 职责                                                                 |
| -------------------- | ------------ | -------------------------------------------------------------------- |
| 场景定义与 TODO 模板 | 业务版本资产 | 表达业务目标、功能脚本调用、依赖、重复、分支、输入输出映射和预期结果 |
| 运行计划快照         | 一次测试流程 | 启动时冻结场景修订、脚本修订、调用展开结果、页面锚点和变量契约       |
| 运行 TODO 实例       | 一次测试流程 | 表示一个具体功能脚本调用及其依赖、输入、状态、输出和阻碍关系         |
| 执行尝试             | 一次派发     | 记录子代理的一次实际执行、证据、检查点、副作用及结果                 |

业务版本复制场景定义和 TODO 模板，不复制运行计划、运行 TODO、执行尝试、实际数据或证据。

## 2. 场景定义

测试场景是完整业务目标和验收单位，可以跨页面、跨功能模块调用多个功能脚本。场景定义至少包含：

- 稳定场景标识、名称、业务目的、PRD 来源和场景修订。
- 场景级前置条件、最终业务验收标准和允许使用的页面范围。
- 功能脚本调用节点，每个节点都有稳定调用标识、目标脚本、输入映射和输出映射。
- 调用节点之间的依赖、顺序提示、重复规则和分支条件。
- 失败传播、清理/补偿和需要主代理决策的边界。

功能脚本调用节点引用脚本的逻辑身份；创建运行计划时再绑定经过验证的精确脚本修订。

## 3. 调用图与控制流

- 首期场景调用图必须是有向无环图，不能用回边表达无限循环或不确定次数的 `while`。
- 依赖关系决定节点何时可运行；显示顺序只用于同等条件下的稳定排序，不能代替依赖。
- 普通依赖默认要求上游成功且所需输出已确认。
- 清理、证据汇总等节点可以声明“等待上游结束”，在上游失败后继续执行，但不能覆盖或隐藏原失败。
- 分支条件只能读取已确认的脚本输出、运行变量或上游结果，并使用受控比较规则；不能执行任意代码，也不能只依赖模型临时判断。
- 场景没有定义但运行中确实需要的分支，由主代理暂停或追加有原因的运行计划修订，不静默改写原场景。

## 4. 重复调用

首期支持两类有界重复：

1. 明确次数，例如连续创建 3 个用户。
2. 对已知数据集合逐项调用，例如为输入用户列表逐个创建账号。

重复在派发前展开成拥有独立身份的运行 TODO 实例。每个实例有独立输入、输出、状态和证据；不支持运行时未知上限的业务循环。

重复调用的输出默认按展开顺序汇总为数组。场景也可以显式导出其中某一项，但不得通过覆盖同名变量丢失其他实例结果。

## 5. 输入、输出与运行变量

- 每个运行 TODO 的输入都来自显式映射：固定值、版本配置、密钥引用、场景输入或已确认的上游输出。
- 输出以调用实例命名空间保存，例如“调用实例 + 输出名”；需要给后续节点使用时，由场景显式导出别名。
- 已确认输出默认不可原地覆盖。需要累计数据时使用声明的集合输出，避免隐式共享可变状态。
- 子代理只获得当前页面任务授权的输入和输出槽位，不能读取或修改整个运行上下文。
- 未确认部分输出、副作用线索和敏感值不进入普通运行变量；其使用规则遵循功能脚本契约。

## 6. 运行计划快照与修订

主代理启动测试流程前生成不可变的基础运行计划快照，至少绑定：

- 业务版本和部署/Git 标识。
- 场景及其精确修订。
- 每个调用的功能脚本精确修订。
- 展开后的运行 TODO、依赖、分支、输入输出映射和页面锚点。
- 运行变量定义、密钥引用和最终验收标准。

业务版本资产在运行中发生修改时，不得静默改变已经启动的基础计划。脚本修复、意外登出恢复、临时清理或其他受控调整通过追加式计划修订记录，包含原因、决策者、替换的脚本修订或新增任务及时间。基础快照和历史修订都保留，确保结果可以解释。

## 7. TODO 与子代理派发

- 一个运行 TODO 对应一个展开后的功能脚本调用，是依赖、结果和证据关联的最小编排节点。
- 主代理可以把同一页面上连续、已就绪且不存在中间决策点的一个或多个运行 TODO 组成页面任务，串行派发给一个子代理，以复用当前页面状态和页面级代理上下文。
- 页面任务只是运行时派发信封，不是新的业务资产；其中每个 TODO 仍分别记录输入、输出、状态、证据和副作用。
- 子代理只能按派发顺序执行授权 TODO，不能新增、删除、重排或跳过调用。
- 页面任务中任一 TODO 失败、中断、阻塞或等待决策时，子代理停止后续 TODO 并上报；主代理重新计算调用图后再派发。
- 首期主代理任一时刻只派发一个页面任务，所有浏览器动作继续使用同一串行执行链。

## 8. 状态与执行尝试

运行 TODO 必须能够区分以下语义；精确 token 和持久化转换表在状态机技术设计中确定：

- 等待依赖、已就绪、执行中和通过。
- 业务失败或执行失败。
- 前置条件明确缺失造成的阻塞。
- 登出、页面丢失或连接中断等可恢复中断。
- 等待主代理或用户决策。
- 因上游依赖失败而跳过。
- 用户取消。

每次实际派发产生新的执行尝试。失败、超时或中断的尝试及其证据不能被后续重试覆盖；运行 TODO 只有在某次经过完整验证的尝试通过后才能成为通过。

## 9. 失败传播、恢复与清理

- 上游没有提供依赖节点所需的成功结果或确认输出时，下游标记为依赖跳过并记录具体上游，不计为通过。
- 与失败节点没有依赖关系的 TODO 可以继续执行。
- 意外登出等可恢复中断先结束当前执行尝试；主代理可以追加登录任务，检查页面与副作用后再恢复原 TODO 或创建新尝试。
- 需要改变 PRD、业务断言、数据安全边界或场景含义的决策会暂停整个测试流程；决策写入当前业务版本后，主代理再追加计划修订并恢复。
- 清理和补偿必须是显式功能脚本调用，通常使用“等待上游结束”依赖；隐式回滚、隐藏失败或在子代理内部偷偷清理均不允许。
- 清理节点自身也必须检查前置条件和副作用。清理成功不会把原业务失败改成通过。

## 10. 启动前校验

运行计划开始前必须验证：

- 调用图无环，所有依赖和脚本引用存在。
- 所有必填输入可解析，所有输出引用都指向真实上游。
- 重复次数和数据集合有明确上限。
- 同名导出不存在未声明覆盖，集合输出规则明确。
- 条件分支可由受控数据确定，不含任意表达式或代码。
- 页面范围、登录前置、密钥引用、清理节点和最终验收标准完整。
- 场景及所有脚本均已绑定精确修订。

校验失败时不得启动浏览器动作，而应把缺口返回给主代理修正或决策。

## 11. 示例

“批量删除用户”场景可以定义：

1. “新增用户”调用模板按 3 组输入展开为 3 个运行 TODO。
2. 三个 TODO 的成功输出汇总为用户标识数组。
3. “批量删除用户”TODO 依赖三个创建 TODO 成功，并消费该数组。
4. 独立的清理 TODO 等待批量删除结束；仅在仍存在残留用户且主代理确认资源身份后执行。

如果第二个创建动作超时，相关执行尝试先记录现场。主代理检查用户是否已经创建：确认成功时可发布该输出并继续；状态未知时不得盲目创建第二次，也不得执行依赖完整数组的批量删除。

## 12. 当前实现差距

- 当前 `test_scenarios` 直接归属一个功能模块，只保存描述、测试数据和排序，不能跨模块/页面表达调用图。
- 当前 `scripts` 归属 scenario，而不是由场景调用模块下的独立功能脚本。
- 当前 `/execution/run-all` 只遍历项目下所有脚本并逐个执行，没有依赖、输入输出映射、重复展开、分支或依赖跳过语义。
- 当前基础设施错误或超时会直接重试一次，没有先确认浏览器副作用，不符合目标恢复契约。
- 当前 `execution_runs` 只关联单个脚本，状态只有 running/pass/fail/error/timeout，没有运行计划、TODO、执行尝试、阻塞、中断、决策暂停或计划修订模型。
