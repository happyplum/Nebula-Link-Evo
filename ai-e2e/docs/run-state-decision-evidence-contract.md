# AI E2E 运行状态、决策与证据契约

> 状态：主体目标设计已确认，安全审批边界仍有一项关键策略待确认。
> 更新时间：2026-08-12。
> 本文定义测试流程从调度到结果汇总的状态、失败传播、决策记录、证据包和人工控制语义。数据库字段、API 路径和 UI 布局可以在详细设计中调整，但不同层级状态不得重新混为一个字段。

## 1. 核心原则

- 项目工作流状态、测试流程状态、运行 TODO 状态、执行尝试结果、Agent 会话状态和浏览器操作状态相互独立。
- 事实只能追加或被新记录显式取代；失败尝试、人工决策和已发生副作用不得被重试覆盖。
- UI 展示后端持久化快照和事件，不从本地进度条、对话文本或最后一条 SSE 猜测权威状态。
- 暂停、待决策、前置阻塞和意外中断不等于业务失败；跳过也不等于通过。
- 证据采集失败不能改变测试结果，只会把证据完整度标记为不完整。

## 2. 分层状态模型

### 2.1 项目工作流

现有项目状态 `draft → configuring → analyzing → analyzed → exploring → explored → generating → ready → running → completed` 只表示项目准备阶段，不承担单次测试流程、TODO 或浏览器操作状态。

项目可以存在多次历史测试流程；一次流程结束不应抹去项目仍可再次运行的事实。目标实现时应把项目“当前阶段”与具体测试流程结果解耦。

### 2.2 测试流程生命周期与结果

生命周期用于回答“流程现在能否继续调度”：

```text
created → planning → ready → running ↔ paused → completing → completed
                                  └────→ cancelling → cancelled
```

| 生命周期 | 语义 |
|---|---|
| `created` | 已创建，尚未冻结运行计划。 |
| `planning` | 正在校验版本、部署、参数并展开调用图。 |
| `ready` | 基础运行计划已冻结，可开始调度。 |
| `running` | 主代理正在调度或等待一个活动页面任务结果。 |
| `paused` | 不再派发新操作，保存暂停原因和检查点；可以恢复。 |
| `completing` | 不再执行普通 TODO，正在汇总结果或执行显式收尾。 |
| `completed` | 运行已封存，不再变化。 |
| `cancelling` | 正在取消未开始工作并等待活动原子操作到达安全边界。 |
| `cancelled` | 运行被取消并封存；已发生副作用不会自动回滚。 |

终态结果单独记录：

- `passed`：所有必须 TODO 通过，没有业务失败、未解决阻塞或依赖跳过。
- `failed`：至少一个必须 TODO 最终失败、阻塞或因依赖被跳过；独立 TODO 的通过仍保留在汇总中。
- `cancelled`：用户或策略取消流程，不折算为失败或通过。

运行汇总同时保留通过、失败、阻塞、中断后恢复、跳过、取消和证据不完整的数量，不能只展示一个总状态。

### 2.3 运行 TODO 状态

一个 TODO 对应冻结运行计划中的一次具体功能脚本调用：

| 状态 | 语义 | 可否继续 |
|---|---|---|
| `waiting_dependencies` | 等待上游 TODO 产生必须输出。 | 上游变化后自动重算 |
| `ready` | 依赖和输入已满足，可派发。 | 是 |
| `running` | 已交给一个页面任务，存在活动执行尝试。 | 等待尝试结束 |
| `waiting_decision` | 需要主代理或用户裁决。 | 决策持久化后 |
| `blocked` | 缺少登录、权限、环境、数据等外部前置条件。 | 主代理追加前置任务或明确终止后 |
| `interrupted` | 登出、错误页面、连接丢失等意外打断，恢复条件明确或待检查。 | 主代理完成恢复检查后 |
| `passed` | 功能脚本全部硬断言通过并发布输出。 | 终态 |
| `failed` | 在当前运行策略内不可恢复或修复/重试已结束。 | 终态 |
| `skipped` | 因明确上游失败、缺失输出或策略决定而未执行。 | 终态 |
| `cancelled` | 运行取消时尚未完成。 | 终态 |

`blocked`、`interrupted` 和 `waiting_decision` 是可恢复状态，不立即触发依赖跳过。只有主代理把 TODO 收敛为 `failed`、`skipped` 或 `cancelled` 后，才向下游传播终态影响。

### 2.4 执行尝试结果

每次派发都创建新的执行尝试；一次尝试只有一个不可变终态结果：

- `succeeded`
- `assertion_failed`
- `execution_failed`
- `precondition_blocked`
- `recoverable_interruption`
- `decision_required`
- `outcome_unknown`
- `cancelled`

尝试结果与原因分类分开。比如“意外登出”是 `recoverable_interruption`，根因可为 `authentication_expired`；“点击超时且无法确认是否提交”是 `outcome_unknown`，不能归为普通 `execution_failed`。

### 2.5 Agent 与浏览器操作状态

- Agent 任务会话沿用 AI 服务自身的 running/paused/interrupted/cancelled/completed 等状态，只说明模型/工具循环，不作为 TODO 结果。
- 浏览器原子操作使用 accepted/queued/running/success/failed/cancelled/outcome_unknown，只说明该浏览器操作。
- Agent 被中断时，已经下发的浏览器操作可以仍在完成；TODO 必须先查询操作结果，再决定尝试结果。

## 3. 失败与中断分类

| 分类 | 默认处理 | 是否属于业务失败 |
|---|---|---|
| `business_assertion` | 固化证据，TODO 最终失败；依赖其输出的节点跳过，独立节点继续。 | 是 |
| `script_drift` | 子代理在授权范围内提出新脚本修订，主代理追加计划修订并重试。 | 修复耗尽后是 |
| `precondition_missing` | TODO 进入 blocked，由主代理安排登录、造数、权限或环境前置任务。 | 未解决时影响最终结果，但不伪装成断言失败 |
| `recoverable_interruption` | TODO 进入 interrupted，主代理恢复环境并检查副作用后恢复或重派。 | 否，恢复失败后可转最终失败 |
| `infrastructure` | 对只读或可证明未执行的操作按预算重试；否则暂停检查。 | 否，但耗尽后导致流程失败 |
| `outcome_unknown` | 查询操作账本并检查页面/数据副作用；禁止盲重试。 | 待确认 |
| `decision_required` | 停止相关分支并创建决策请求。 | 否 |
| `cancelled` | 停止未开始工作，记录已发生副作用和可选清理建议。 | 否 |

主代理每次收敛失败必须同时给出：尝试结果、原因分类、是否可恢复、可能副作用、缺失输出、受影响下游、下一步动作和证据完整度。

## 4. 依赖传播与继续执行

- TODO 只有在所有普通依赖 `passed` 且输入绑定完成时才能进入 `ready`。
- 上游最终 `failed`、`skipped` 或 `cancelled` 后，下游若依赖其执行效果或输出，转为 `skipped` 并记录直接上游、缺失变量和传播链。
- 不依赖失败分支的 TODO 可以继续，但主代理仍需重新确认当前页面和共享浏览器状态适合调度。
- 显式清理节点使用“等待上游结束”的完成依赖，可以在上游失败后运行；清理成功不能把原业务失败改为通过。
- 对 blocked/interrupted/waiting_decision 分支，不提前跳过下游；主代理先尝试恢复或作出终止决定。
- 共享资源存在冲突时，即使调用图无数据依赖，主代理也可以追加串行约束；该调整必须进入运行计划修订。

## 5. 决策请求与决策记录

### 5.1 谁可以决定

- 子代理只能提出决策请求，不能自行改变业务断言、任务范围、数据安全边界或场景编排。
- 主代理可以依据已经写入业务版本的规则处理普通运行决策，例如选择已声明的恢复分支、重派、跳过依赖节点或停止流程。
- 超出既有规则、改变需求/验收或触及受保护环境的数据操作时必须请求用户决定。

### 5.2 决策请求内容

每个请求至少包含：

- 决策 ID、请求者、创建时间和当前状态。
- 业务版本、运行、页面任务、TODO、尝试和步骤关联。
- 问题分类：需求歧义、预期结果、范围变化、数据安全、环境权限、恢复路径或其他。
- 已知事实、证据引用、不能继续的原因和影响范围。
- 互斥候选方案、每项影响、主代理推荐项和不决策的后果。
- 需要的决策权限：主代理或用户。

### 5.3 持久化范围

- 只影响本次运行的操作性决定，例如“本次跳过不可用环境”，写入运行决策日志。
- 会改变需求解释、验收口径、脚本维护方式或后续运行的决定，先写入当前业务版本的决策文档，再以决策引用恢复运行。
- 决策记录追加保存，包含决定者、决定内容、理由、时间和证据；后续变更通过新决策显式 supersede 旧记录，不原地改写。
- 被拒绝或撤回的候选也保留审计状态，但不进入生效规则。

### 5.4 首期决策状态

```text
open → answered → applied
   ├→ withdrawn
   └→ expired
```

`answered` 只表示已有决定；只有决定已经写入正确载体并生成恢复/计划修订后才是 `applied`。恢复命令必须引用已 applied 的决策 ID。

## 6. 暂停、恢复、取消与人工接管

### 6.1 暂停和恢复

- 用户暂停或主代理等待决策时，停止派发新 TODO 和浏览器操作；活动原子操作到达明确结果或 `outcome_unknown` 后生成检查点。
- 暂停页面必须展示原因、请求者、活动操作、可能副作用、等待对象和允许的下一步。
- 恢复前固定检查业务版本/部署仍有效、浏览器会话与 Tab 存在、页面身份和登录态正确、未决操作已收敛、输入变量仍有效。
- 检查失败时不得直接恢复原 Agent 对话；主代理创建恢复任务、计划修订或新上下文。

### 6.2 取消

- 取消需要展示仍在运行的操作、已经产生的声明副作用和可用清理脚本，并要求确认。
- 取消未开始 TODO 和排队操作，不回滚已经完成的动作；显式清理是独立 TODO，拥有自己的结果和证据。
- 普通取消不关闭浏览器，保留现场供查看；关闭会话是单独控制并需要再次确认。

### 6.3 人工接管

首期默认只读观看，不允许人与 Agent 同时操作页面。未来如支持人工接管，必须：

1. 先暂停主代理和子代理，等待活动原子操作结束。
2. 为用户签发独占人工控制租约，记录人工操作。
3. 释放接管后废弃旧页面检查点，重新采集页面/DOM/登录态与副作用。
4. 由主代理基于新检查点决定恢复或重派。

人工接管不能绕过版本、运行或数据安全策略，也不能把手工结果直接标记为脚本通过。

## 7. 证据所有权与不可变证据包

### 7.1 所有权

- `proxy-adapter` 生成浏览器侧原始截图、DOM、操作事件和媒体片段，短期保存并返回产物引用。
- `ai-chat-service` 保存 Agent/工具调用审计，但不作为业务证据目录。
- `ai-e2e` 创建不可变证据清单，将需要长期保留的原始产物提升到运行证据存储，并关联版本、TODO、尝试、步骤和操作。

证据包使用内容哈希和只读 manifest 校验完整性；任何补充材料以新条目追加，不改写旧文件及其哈希。

### 7.2 最低证据内容

每个执行尝试至少记录：

- 冻结的版本、部署/Git 标识、场景、功能脚本修订、TODO、尝试、页面锚点和 Tab。
- 输入变量的脱敏快照、预期输出和硬断言。
- 语义步骤及其原子操作 ID、时间、目标解析依据、结构化结果和错误分类。
- 开始/结束 URL、标题、页面快照引用和关键验证实际值。
- 输出、部分数据、声明副作用和后续阻碍评估。
- Agent 任务和视觉调用引用，不把模型推理文本作为唯一证据。

任何失败、阻塞、中断、待决策或结果不确定尝试还必须包含：

- 现场截图；能够确定目标时保存标注截图。
- 失败附近 DOM 快照、页面身份、当前步骤、期望与实际结果。
- 已完成步骤、未决原子操作、可能副作用和缺失输出。
- 建议恢复条件、受影响下游和证据采集错误。

如果截图或 DOM 采集失败，尝试仍按真实结果结束，但 evidence completeness 标记为 `partial` 或 `failed`，并记录采集失败原因。

### 7.3 证据完整度

- `complete`：策略要求的所有证据已固化并校验。
- `partial`：核心结果存在，但至少一个要求产物缺失或无法脱敏。
- `failed`：没有取得最低现场证据；测试结果仍保留，运行汇总必须显著提示审计风险。

证据完整度不是测试结果；不能因为证据齐全把失败改成通过，也不能因截图失败把业务断言失败改成基础设施错误。

## 8. 采集与保留策略

### 8.1 默认采集级别

| 级别 | 内容 | 默认用途 |
|---|---|---|
| `standard` | 操作账本、语义步骤、检查点截图/DOM、断言实际值、失败现场 | 普通运行默认 |
| `diagnostic` | standard + 每步前后截图、受限 console/network 元数据、失败前后媒体片段或 trace | 调试运行或重现难题 |
| `minimal` | 只保存脱敏结构化结果和失败必要现场 | 高敏数据环境 |

实时视频始终用于可视执行，但默认不等于永久录像。历史“重放”优先使用语义步骤、操作时间线、截图和短媒体片段，不重新执行副作用动作。

### 8.2 默认保留

- 运行结果、证据 manifest、决策和哈希随运行记录保留。
- 成功运行的原始标准证据默认保留 7 天。
- 失败、阻塞、待决策和结果不确定证据默认保留 30 天。
- 用户可以 pin 重要证据延长保留；删除运行或证据属于独立、可审计操作。
- `proxy-adapter` 原始短期产物必须在自身清理前被 `ai-e2e` 提升或明确标记丢失。

保留期是可配置默认值，不改变证据清单和审计语义。

## 9. 脱敏与访问安全

- 输入、输出和运行变量按 Schema 标记 `public`、`sensitive` 或 `secret`；默认未知字段按 `sensitive` 处理。
- 密码、Token、Cookie、Authorization、会话存储、私钥和密钥变量不进入截图之外的持久证据，结构化字段只保存已脱敏摘要。
- DOM、截图和视频可能包含 PII；长期保存前应用项目脱敏规则。无法可靠脱敏时进入受限存储并缩短保留，不得把原始内容写入普通日志。
- 网络采集默认只保留方法、脱敏 URL、状态码和时间；请求/响应体采用明确 allowlist，禁止全量默认采集。
- UI 按项目权限控制证据、决策和下载；下载与删除进入审计日志。具体身份/权限系统在实现前设计。

## 10. 权威事件流

- `ai-e2e` 持久化每个运行的单调 `runSeq` 领域事件；事件包含 event ID、发生时间、状态版本、实体引用和因果/关联 ID。
- 命令先以幂等 command ID 持久化状态变化，再发布事件；重复暂停、恢复、取消或决策提交不能重复产生业务效果。
- SSE 是持久状态的投影，不是状态源。连接时先发送 `run.snapshot` 和当前 `runSeq`，随后发送新事件；发现序号缺口时 UI 重新获取快照。
- UI 不再通过每收到一条 `execution.progress` 就本地增加 5% 推断进度；进度来自冻结 TODO 数量、终态数量和当前步骤。
- 事件至少覆盖运行、TODO、尝试、页面任务、决策、证据和用户控制；浏览器原子事件由 `ai-e2e` 关联后投影到同一时间线。

## 11. 目标 UI 功能面

执行工作区必须提供以下功能面，具体视觉布局后定：

### 11.1 运行总览与控制

- 展示业务版本、部署/Git 标识、场景、生命周期、最终结果、进度、开始时间和当前执行者。
- 提供开始、在安全边界暂停、恢复、取消以及独立关闭浏览器控制；按钮可用性由服务端状态和版本号决定。
- 取消前显示已发生副作用、未决操作和可选清理，不使用一个无解释的“停止”按钮。

### 11.2 实时浏览器与当前任务

- 实时展示 `proxy-adapter` 画面、活动 Tab、操作动画和连接质量。
- 同时展示当前页面、模块、功能脚本、TODO、语义步骤、目标说明、正在验证的断言和最近实际结果。
- 默认不要求用户查看 TypeScript 或模型对话才能理解执行过程。

### 11.3 运行时间线与依赖

- 一条时间线关联主代理调度、页面任务、Agent 工具调用、浏览器操作、验证、决策和证据。
- 节点显示真实状态、起止时间、尝试次数和证据完整度，不把重复步骤按同名合并。
- 调用图显示哪些 TODO 因哪一个上游、哪个缺失输出而跳过，哪些独立分支仍继续。

### 11.4 决策中心

- 集中展示 open 决策的事实、证据、候选方案、推荐项、影响范围和所需权限。
- 用户提交决定后先看到持久化结果及将产生的计划修订，再允许恢复。
- 运行级决定和业务版本长期决定明确区分。

### 11.5 证据与报告

- 按运行 → TODO → 尝试 → 步骤浏览截图、DOM、断言实际值、操作账本和诊断。
- 显示证据完整度、脱敏状态、保留到期时间和是否已 pin。
- 报告区分业务失败、脚本漂移、前置阻塞、中断恢复、基础设施错误、依赖跳过和取消，不把它们合成一个 fail 数字。

## 12. 当前实现差距

- 当前项目状态机只表达项目准备阶段；`execution_runs` 只关联一个脚本并混用 running/pass/fail/error/timeout，尚无流程、TODO、尝试、决策和证据完整度状态。
- 当前取消子进程会被记录为 timeout，无法区分用户取消、真实超时和结果不确定。
- 当前 SSE 事件只有时间和简单 payload，没有持久 event ID、每运行序号、快照恢复、TODO/尝试/决策/证据事件。
- 当前 UI 通过本地 `isRunning` 和每个 progress 事件增加 5% 推断状态；同名步骤会合并，不能准确展示多次调用和尝试。
- 当前运行详情只读取可选步骤 JSON 和单张 base64 截图；失败日志与截图路径没有不可变证据 manifest、哈希、脱敏、保留或完整度语义。
- 当前 AI 修复有 run 级诊断、变更比例与人工审批基础，但审批对象仍是旧 TypeScript 脚本修改，不是版本决策、页面任务恢复或追加式运行计划修订。

## 13. 实现前仍需精确定义

- 各层实体表、状态 token、command 幂等记录与 run event 持久化已在 `target-data-model.md` 锁定；精确服务 API/SSE payload 仍由跨服务契约定义。
- 证据对象存储、内容哈希、提升事务、脱敏管线、访问权限和清理任务。
- UI 组件层级、实时画面协议、依赖图表现和操作动画样式。
- 不同环境与副作用风险等级下，哪些动作必须由用户审批；这是当前剩余的关键产品策略。

## 14. 验收原则

1. 同一时刻可以准确回答运行、TODO、尝试、Agent 和浏览器操作各自处于什么状态，不用一个 status 字段代替全部层级。
2. 登出进入 recoverable interruption，待决策进入 waiting decision，用户取消进入 cancelled，均不会被错误统计为业务断言失败。
3. 失败分支只跳过真实依赖它的节点；独立节点可以继续，跳过节点保留完整传播链。
4. 任何重试、修复或恢复都创建新尝试并引用旧证据，不覆盖失败历史。
5. 决策没有持久化到正确载体前，相关 TODO 不能恢复。
6. 失败即使证据采集失败也保持失败，同时显著标记证据不完整。
7. SSE 断开重连后，UI 通过权威快照恢复，不依赖本地累计状态。
8. 用户可以从画面和时间线理解动作、验证、失败与恢复，不必读取脚本。
9. 取消不会伪装成超时，也不会隐式关闭浏览器或回滚副作用。
10. 证据中的秘密字段被移除，敏感截图/DOM 有明确权限与保留策略。
