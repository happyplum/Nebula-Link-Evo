# AI E2E 产品需求基线

> 状态：已确认目标需求，尚未全部实现。
> 更新时间：2026-08-20。
> 本文记录产品边界与验收语义，不规定数据库表、接口字段、脚本 DSL 语法或实施顺序。当前实现状态以代码和 `ai-e2e/PRODUCT-SPEC.md` 为准。

## 1. 产品定位

`ai-e2e` 是基于 PRD 与已完成网页的 E2E 测试业务层。它负责把需求理解、页面探索、测试资产生成、场景编排、可视执行、结果验证和局部修复组织成可维护闭环。

系统分为三层：

- `proxy-adapter`：浏览器与 Playwright/CDP 能力的唯一所有者，通过 MCP 提供页面分析、操作、实时画面和执行证据。
- `ai-chat-service`：AI 基础能力层，提供分析/决策模型、单次视觉分析、MCP 工具编排、受限 Agent task 命令/事件控制面和本地只读声明式 Skills runtime；通用视觉 v2 与完整授权仍待实现。
- `ai-e2e`：E2E 业务层，持有 PRD、业务版本、页面、功能模块、功能脚本、测试场景、任务依赖、运行上下文和结果报告。

首次提供 PRD 与目标链接时，系统从零分析并生成测试资产；后续运行优先加载已有资产，由子代理验证并在职责范围内修正。

## 2. 领域层级

```text
业务版本
├─ PRD 原文、解析结果与决策文档
├─ 页面（URL + 路由/查询参数锚点）
│  └─ 功能模块
│     └─ 多个功能脚本
└─ 测试场景
   └─ 编排多个功能脚本调用
      ├─ 顺序与依赖
      ├─ 重复调用
      ├─ 输入输出绑定
      └─ 预期结果
```

### 2.1 页面

- 逻辑页面由不含 Origin 的规范化路由模板与身份参数约束唯一标识；部署 Base URL、动态资源 ID、分页、搜索和追踪参数不直接成为页面身份。
- 页面定义保存路由模式和参数 Schema；某次运行的页面锚点由页面定义、冻结部署和已校验参数绑定组成，再解析为实际 URL。
- 一个页面可以包含多个有顺序的功能模块。
- 弹窗、抽屉和无稳定导航身份的局部状态不单独建页；一个功能模块只归属一个主要页面定义。
- DOM 基线、元素定位信息和参考截图以命名基线变体归属于页面版本资产，但每次执行仍必须重新检查当前页面状态。

完整页面与版本资产契约见 `version-page-asset-contract.md`。

### 2.2 功能模块与功能脚本

- 功能模块是页面内的业务功能分组，例如“用户维护”。
- 一个功能模块可以拥有多个功能脚本，例如新增用户、编辑用户、单个删除和批量删除。
- 功能脚本是最小的复用、独立执行、验证、修复和重复调用单元。
- 功能脚本可以操作当前页面内的弹窗、抽屉或页面跳转，但不得继续承担另一个页面模块的业务职责。
- 跨页面业务由测试场景组合不同页面的功能脚本完成。

### 2.3 测试场景与 PRD 流程

- 测试场景是完整业务目标和验收单位，可以包含多个功能模块、多个功能脚本和多个页面。
- PRD 负责形成测试流程与 TODO，定义脚本调用顺序、依赖、重复次数、参数传递和预期结果。
- 同一功能脚本可以在场景内重复调用。例如批量删除前可以多次调用新增用户脚本。
- 一个脚本的输出可以成为后续脚本的输入。例如新增用户输出用户标识，删除用户消费该标识。
- 脚本只完成自身业务操作，不在内部擅自编排登录、造数或其他场景外脚本。
- 首期场景使用有向无环调用图；有界重复在运行前展开，运行时未知上限的循环不进入功能脚本或调用图。
- 业务版本保存场景定义与 TODO 模板；每次测试流程生成独立运行计划、运行 TODO 和执行尝试，不把运行状态写回场景定义。

完整编排契约见 `scenario-orchestration-contract.md`。

## 3. 业务版本与复制

- 业务版本由用户显式创建。
- 版本记录来源版本，并可记录部署标识和 Git 标识。
- `copy` 产生完全独立、可修改的资产快照，后续生成和修复不得覆盖来源版本。
- 复制范围包括 PRD、解析结果、决策文档、页面定义与参数 Schema、功能模块、功能脚本、测试场景、TODO 模板、变量定义、DOM 基线、元素定位信息和参考截图；运行时具体参数绑定不属于版本资产。
- `copy` 复制当前有效资产修订并生成全新身份，在同一事务内重建内部引用；来源资产和修订只作为审计元数据。
- 新版本内的资产拥有独立身份和引用关系；来源版本只用于追溯，不形成可变共享引用。
- 编辑事件历史、运行计划、运行 TODO、执行尝试、失败证据、临时运行变量、实际测试数据、登录状态、Cookie、Token 和其他密钥不随版本复制。
- 被复制的 DOM、定位和截图只是新版本的初始参考；每次运行仍执行重新检查。

## 4. 代理职责

### 4.1 主代理

主代理负责：

- 作为 `ai-e2e` 内由持久状态驱动的确定性工作流协调器运行，而不是依赖一个无限延续的模型对话；authoring/run 的阶段、任务、尝试、覆盖率、决策、检查点和事件是恢复源。
- 理解完整 PRD，生成或维护测试流程、TODO 和依赖关系。
- 维护全局运行上下文及功能脚本之间的数据传递。
- 按页面和场景职责拆分任务，向子代理派发明确的输入、脚本调用、预期结果和允许写回的输出。
- 接收子代理结果，决定继续、暂停、插入前置任务、恢复、跳过或结束流程。
- 处理登录、测试数据准备等跨场景前置条件；子代理不得自行补做。
- 对需要裁决的问题作出决策；会影响需求、验收或后续维护的决定必须先写入当前业务版本的决策文档，再恢复执行。
- 汇总通过、失败、中断、暂停和跳过结果及其证据。

主代理可以调用视觉模型完成一次明确的页面分析，但视觉模型不接管调度。

### 4.2 子代理

- 子代理负责主代理派发的页面场景片段，只执行任务中明确授权的功能模块和功能脚本。
- 子代理执行脚本、重新检查页面、验证结果，并在职责范围内修正失效脚本，最后结构化汇报结果、输出数据和证据。
- 子代理不得擅自登录、创建缺失数据、调用场景外脚本、改变业务断言或扩大任务范围。
- 子代理发现意外登出、缺少外部前置条件或进入错误页面时，当前执行尝试失败并上报，由主代理安排后续动作。
- 子代理认为需要主代理裁决时，应暂停操作、保存现场和恢复检查点，并提交问题、影响和候选方案。
- 大多数派发创建干净的新代理上下文。对于登出等可恢复的意外中断，主代理可以恢复原子代理上下文；如果上下文已失效，则创建干净上下文并加载原任务、检查点和获授权变量。
- 代理记忆不是长期资产；可复用结论必须写回版本文档、页面资产或功能脚本。

### 4.3 视觉模型

- 主代理和子代理都可以调用视觉模型。
- 每次视觉调用只处理一个边界明确的分析任务，例如识别页面状态、解释截图与 DOM、查找目标元素或比较变化。
- 调用方必须为每次调用提供完整输入。
- 视觉模型不保存流程状态、不连续执行任务、不调度脚本、不操作浏览器，也不决定下一项业务任务。
- 视觉输出必须是可序列化证据，不得跨服务返回 `Page`、`Locator` 或 `ElementHandle` 等进程内 Playwright 对象。

## 5. 功能脚本与执行方式

### 5.1 权威脚本资产

- 系统内的权威资产是结构化、参数化的语义功能脚本，不是要求用户阅读的传统 Playwright `.spec.ts` 文件。
- 功能脚本应能表达业务步骤、浏览器动作、目标语义与定位依据、变量引用、前置检查、操作后验证、预期输出和恢复检查点。
- 场景通过受控的编排结构调用脚本，而不是把完整测试流程硬编码进单个脚本。
- 首期功能脚本是线性步骤序列，不包含通用条件分支、业务循环或其他功能脚本调用；重复、分支和跨脚本依赖由场景调用图及主代理处理。
- 脚本前置条件只负责检查，不能隐式补做登录、造数或场景外任务；输入必须显式声明并由场景调用映射。
- 脚本输出在全部业务断言通过后才发布到运行上下文；失败或中断产生的部分输出只作为未确认数据上报，必须经主代理重新检查后才能使用。
- 创建、更新、删除和认证变化等副作用必须声明并在重试前检查；传输失败或超时不代表动作没有生效。
- 直接导出并运行 `npx playwright test` 不是当前验收目标；未来可以作为派生产物，不得取代系统内的权威语义脚本。

功能脚本的产品契约见 `functional-script-contract.md`；首期 DSL 字段、序列化 Schema、动作/断言白名单、引用与静态校验见 `semantic-script-schema.md`。

### 5.2 唯一浏览器执行链

- `proxy-adapter` 是功能脚本和探索动作的唯一浏览器执行入口。
- `ai-e2e` 不应为目标运行链启动独立 Playwright/Chromium 进程；主代理、子代理和修复验证不得使用不可观察的浏览器操作旁路。
- 语义指令通过 `ai-chat-service` 的 Agent/MCP 能力发送给 `proxy-adapter`，由其映射为 Playwright 操作。
- 所有浏览器操作都必须在实时画面中可见，并能关联到当前场景、功能脚本和步骤。
- 目标体验是让人通过实时画面、操作说明和结果状态理解测试过程，而不必阅读底层脚本。
- 操作记录必须支持复现；后续可在 `proxy-adapter` 的指令执行画面上增加高亮、鼠标移动、点击、输入、滚动和断言等操作动画。
- 执行采用“一个语义步骤一次受控推进”：子代理完成重新检查、目标解析、原子动作与后置验证后才能进入下一步，不把完整脚本或任意 JavaScript 批量交给浏览器网关。
- 浏览器原子操作必须有全局唯一且可查询的幂等身份；无法确认动作是否发生时进入结果不确定态，由主代理安排副作用检查，不能按普通失败盲目重试。
- `proxy-adapter` 只解释通用浏览器会话、Tab、目标、动作、观测与产物；场景、TODO、功能脚本和业务断言仍由 `ai-e2e` 解释。

完整代理与浏览器执行契约见 `agent-browser-execution-contract.md`。

### 5.3 固定重新检查

每次执行都包含重新检查，而不是只在版本复制或脚本修复后检查一次：

1. 获取当前页面状态及最新 DOM/截图证据。
2. 检查页面身份、路由、登录状态和场景前置条件。
3. 每个操作前重新解析并确认目标元素。
4. 操作后验证页面变化和业务结果。
5. 恢复中断任务前检查中断前操作是否已产生副作用。

恢复单位是经过状态确认的语义步骤，不是脚本代码行。状态不确定时不得盲目重复可能产生副作用的操作。

### 5.4 环境与副作用策略

- 环境由冻结 deployment revision 的 `environment` 决定，客户端、模型和脚本不能覆盖。
- 功能脚本的副作用必须声明资源、可验证身份、有限最大数量、可逆性、应用检查和重试策略；未声明、无界或无法分类的潜在写动作在所有环境拒绝。
- local/test 自动执行已声明且有界的副作用。
- staging 的单项、非不可逆 create/update 和认证会话变化自动执行；删除、批量、不可逆或文件上传在运行/验证开始前做一次计划级用户审批。
- production 只允许显式登录/退出/会话刷新、导航、只读观测和断言；create/update/delete、上传或会提交业务数据的动作硬拒绝，不提供 v1 审批越权。
- staging grant 只绑定一个精确 run/authoring job、deployment revision、策略版本和安全相关投影。纯 locator 修复可沿用；新增/扩大副作用必须重新审批，下一次运行不得复用。

完整策略见 `environment-side-effect-policy-contract.md`。

## 6. 运行上下文、失败与恢复

### 6.1 运行上下文

- 全局运行上下文按一次测试流程隔离，由主代理维护。
- 子代理只读取任务授权的输入，并只写回任务声明的输出。
- 运行变量可以贯通不同功能脚本，例如把新增用户的输出交给后续删除脚本。
- 运行变量和实际测试数据不写入业务版本，也不泄漏到其他测试流程。

### 6.2 运行计划与 TODO

- 测试流程启动时冻结业务版本、场景修订、功能脚本修订、展开后的调用图及变量映射，形成不可变基础运行计划。
- 一个运行 TODO 对应一个具体功能脚本调用；每次子代理派发形成独立执行尝试，失败和中断证据不能被重试覆盖。
- 修复脚本、插入登录或清理任务等运行中调整使用追加式计划修订，保留原始计划和修改原因，不静默改写场景定义。
- 同一页面上连续、已就绪的 TODO 可以组成页面任务交给一个子代理，但每个 TODO 仍独立记录结果、输出、副作用和证据。
- 调用图的普通依赖要求上游成功；显式清理节点可以等待上游结束后运行，但不能隐藏上游失败。

### 6.3 浏览器会话与串行调度

- 首期采用单执行链：一个主代理在任一时刻只调度一个执行型子代理，等待该子代理完成、暂停或上报中断后，才派发下一项任务。
- 首期每个 `proxy-adapter` 进程全局最多一个活动浏览器执行会话；authoring verification 和正式 test run 共用一个公平 FIFO，不能把 singleton Context 包装成多个可并发的逻辑 session。
- 首期一个浏览器执行会话只能绑定一个 `BrowserContext`，同一时刻只能存在一个已确认活动业务身份或匿名态；运行中不得通过切换 Context、导入另一份 storage state 或保留并存 Cookie 来隐藏切换账号。
- 跨账号或跨角色流程仍可执行，但必须在场景中显式编排退出与登录功能脚本，并把每个 TODO 所需身份及认证变化写入冻结运行计划。认证变化只有在脚本硬断言通过后才更新已确认活动身份。
- 子代理只检查任务包声明的所需身份。发现身份不符、意外登出或认证状态无法确认时立即停止并上报；由主代理串行安排身份恢复或切换，子代理不得自行登录。
- 新 run 不继承“已确认身份”结论，认证上下文从 `unknown` 开始并读取当前页面重新确认；即使复用浏览器会话，也不能把上一个 run 的 actor 投影当作本次事实。
- 主代理持有浏览器会话生命周期，只在原子操作安全边界获得 `observe` 租约；子代理只取得页面任务范围内、限制 Tab 和操作集合的短期 `control` 租约，不得打开或关闭共享浏览器。UI live view 始终只读。
- 每个浏览器操作使用稳定 `operationId` 关联请求、结果和证据；传输重试复用同一 ID 并返回既有结果，不能重复执行。
- “一个主代理管理一个子代理”描述的是同一时刻的调度并发度，不要求所有任务永久复用同一个子代理上下文。新的页面场景片段仍可创建干净的子代理上下文，同时继续使用主代理指定的浏览器会话。
- 首期即使页面产生多个 Tab，也只允许一个活动操作流；切换 Tab 后继续串行执行，不并发操作多个页面。
- 同时保持多个认证身份、多 BrowserContext 或多 Tab 并发均不属于 v1。后期并发优先以同一 Playwright 实例内的多 Tab 为执行单元；每个 Tab 必须有独立任务归属和动作队列，且不得由多个子代理同时控制。具体身份隔离、调度和恢复协议在实现该能力前另行设计。

### 6.4 失败、中断、暂停与跳过

- 业务执行失败必须记录，不得通过放宽断言或静默跳过伪造成通过。
- 子代理上报失败时必须说明是否阻碍后续场景、已产生哪些部分数据或页面副作用，以及缺失哪些预期输出。
- 主代理依据 TODO 依赖关系决定影响范围。依赖失败输出的后续任务可以跳过；不受影响的任务可以继续。
- 意外登出属于可恢复中断：子代理停止当前任务并上报，主代理安排登录任务，再依据检查点和副作用检查决定恢复或重派。
- 需要主代理作出业务或验收决策时属于暂停，不等同于测试失败。决策持久化到当前业务版本后才能恢复相关任务。
- 被跳过的任务必须保留原因和上游依赖，不能计为通过。

目标状态按层分离：测试流程生命周期、运行 TODO 调度状态、执行尝试结果、Agent 会话状态和浏览器原子操作状态不得复用一个字段。TODO 明确区分 `waiting_dependencies`、`ready`、`running`、`waiting_decision`、`blocked`、`interrupted`、`passed`、`failed`、`skipped` 和 `cancelled`；blocked/interrupted/waiting_decision 在主代理收敛前不提前向下游传播终态跳过。

完整状态、失败传播和恢复契约见 `run-state-decision-evidence-contract.md`。

## 7. 失败证据

任何失败都必须在上报主代理前固化现场，至少包含：

- 失败时截图；能够确定目标位置时同时保存标注证据。
- 当前 URL、页面标题与 DOM 快照。
- 业务版本、测试流程、场景、功能脚本、脚本调用和失败步骤的关联信息。
- 期望结果、实际结果、已执行步骤和错误说明。
- 脱敏后的输入、输出、部分数据与可能副作用。
- 是否阻碍后续任务及建议的恢复条件。
- 时间信息和可用于关联操作记录的运行标识。

失败证据归属于具体运行，不写回版本基线。只有修复经过重新执行和验证后，新的 DOM 基线、定位信息或功能脚本修订才写入当前业务版本。

`proxy-adapter` 生成浏览器侧原始产物，`ai-e2e` 持有不可变证据 manifest、长期证据索引和业务关联。失败截图/DOM 采集失败不能改变测试结果，只能把证据完整度标为 partial/failed。默认成功原始证据保留 7 天，失败/阻塞/待决策/结果不确定证据保留 30 天，manifest 与运行结果随运行记录保留；实时视频默认用于观察而非永久录像。秘密字段不得进入普通证据，截图/DOM/媒体按项目规则脱敏和限权。

## 8. 脚本修复边界

- 子代理可以在当前页面场景片段内修复 DOM、定位器和交互方式变化造成的功能脚本失效，并重新验证。
- 修复只写入当前业务版本，不覆盖来源版本。
- 需要调用其他场景、补充登录或准备外部测试数据时，必须上报主代理调度。
- 修复如果会改变 PRD 含义、业务预期、断言口径、数据安全边界或其他场景契约，必须暂停并由主代理决策；需要用户决定时由主代理继续上报。

### 8.1 资产生成、复核与激活

- 首次 PRD + URL 使用持久 `bootstrap` authoring job，按需求抽取、页面发现/建模、模块需求、功能脚本 candidate、场景 candidate、真实浏览器验证和版本校验推进。
- copy、部署/Git 变化和正式运行前使用 `recheck`；运行失败或 DOM/交互变化使用 `repair`。
- candidate 的静态 Schema 校验、真实浏览器验证与 current 激活是三个独立门槛；模型自评、旧 run pass 或静态 valid 都不能代替 verified。
- copy 后目标版本的执行资产标为 stale，必须在目标 deployment revision 上重新验证后才能恢复 `valid` 并创建正式 run。
- revision dependency index 由已校验 payload 确定性生成；locator-only 只修当前脚本，交互变化重验引用场景，契约/需求变化扩大依赖范围并暂停决策。
- 完整工作流、coverage、candidate 和影响分类见 `asset-authoring-repair-contract.md`。

## 9. 当前实现与差距

- ai-e2e 只保留 semantic 数据、canonical `/api/v1/*`、结构化 Authoring/Run 和浏览器中心工作台，不提供旧资产、旧路由或任意脚本执行兼容。
- 项目初始化会原子建立 deployment、业务版本、PRD、页面、模块、观察型脚本和场景，并以 bootstrap job 进入真实网页建模。
- Agent task、Vision v2、逐 effect 授权、浏览器 FIFO、依赖传播、恢复/决策、revision verification、证据提升和原子激活已接通。
- 完整参数 Schema/页面匹配与基线采集、独立机器 Schema validator、Agent/browser event stream 直连消费、证据自动脱敏和保留清理仍为技术债。

## 11. 需求验收原则

后续技术方案至少需要证明：

1. 首次 PRD + 链接能够从零生成页面、模块、功能脚本和测试场景资产。
2. 后续运行能够加载同一业务版本，重新检查页面并复用或修复资产。
3. 复制业务版本后修改或修复脚本，不会改变来源版本。
4. 一个场景能够编排多个模块的多个功能脚本，并传递运行数据。
5. 场景定义、运行计划、运行 TODO 和执行尝试相互隔离；运行修复通过可追溯的追加式计划修订完成。
6. 有界重复能够展开为独立 TODO；依赖失败只跳过受影响节点，显式清理节点不掩盖原失败。
7. 功能脚本只能读取声明输入、执行线性职责内步骤，且不能调用其他功能脚本或隐式补做前置任务。
8. 只有全部业务断言通过的脚本才能发布输出；有副作用的操作在未知状态下不能盲目重试。
9. 子代理不能越权处理登录、造数或场景外任务；主代理能够根据上报进行恢复调度。
10. 首期同一测试流程在任一时刻只有一个执行型子代理和一个浏览器动作流，子代理上下文切换不会隐式更换浏览器会话。
11. 主/子代理调用视觉模型时，每次都是独立、单次、完整输入的分析任务。
12. 所有浏览器操作通过 `proxy-adapter` 执行，并在实时画面与步骤记录中可观察。
13. 失败会保存截图与必要现场证据，并评估对后续依赖任务的阻碍。
14. 需要决策的任务能够暂停，决策写入版本文档后再恢复。
15. DOM 或定位变化只修复当前业务版本内受影响的功能脚本，并经过重新执行验证。
16. 同一逻辑页面在不同部署、动态资源 ID、分页或追踪参数下仍能稳定匹配，歧义页面不能进入标准运行。
17. 版本复制生成独立资产身份并重建引用，不复制运行状态、证据、实际数据或秘密。
18. 子代理只能在任务租约内操作指定 Tab 和工具，不能控制共享浏览器生命周期。
19. 浏览器原子操作可通过 `operationId` 去重和查询；结果不确定时必须先检查副作用，不能重复执行。
20. 暂停、Agent 中断和取消不会被误判为已完成动作回滚，恢复从已确认的语义检查点开始。
21. 测试流程、TODO、尝试、Agent 和浏览器操作状态相互独立；取消、登出、待决策和断言失败不会混为同一 fail。
22. UI 通过持久化运行快照和单调事件序号恢复，不能用本地累计百分比推断权威状态。
23. 决策先持久化再恢复；失败证据缺失只降低证据完整度，不改变真实测试结果。
24. 主代理或任一服务重启后可从 authoring job/task/attempt/event 恢复；模型对话不是状态源。
25. candidate 只有静态 valid + 真实浏览器 verified 后才能进入可运行版本；copy 后 stale 资产不能直接运行。
26. locator-only 变化不重写同页面无关脚本；修复范围可由 revision dependency index 和 change kind 解释。
27. 首期一个 proxy 进程全局只有一个活动浏览器执行会话，authoring 与 run 不并发控制 singleton Context。
28. local/test 的已声明有界副作用可自动运行；staging 高风险计划只审批一次，安全投影扩大后必须重新审批。
29. production 可以执行显式认证和只读验证，但任何业务写入/上传在浏览器 control 操作前被硬拒绝且不可用审批绕过。
