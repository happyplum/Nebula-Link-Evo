# 功能脚本需求契约

> 状态：`shipped`。结构化脚本 revision、TypeBox JSON Schema/独立静态 validator、确定性步骤投影、副作用授权、浏览器验证与场景调用已经交付。

## 1. 定位与边界

功能脚本是系统内最小的可复用、可独立执行、可验证和可修复业务单元，例如“登录”“新增用户”“编辑用户”“单删用户”“批量删除用户”。

- 每个功能脚本只归属当前业务版本中的一个功能模块，并声明主要页面锚点。
- 功能脚本只完成一个明确业务目的，不承载完整测试流程。
- 功能脚本不能调用其他功能脚本，也不能自行补做造数或场景外前置任务；除业务目的本身是登录外，登录任务也必须由测试场景和主代理显式编排。
- 登录、退出和账号切换必须由独立功能脚本表达认证变化。场景调用声明执行前/后的 actor 状态；脚本只执行自身认证职责并用硬断言验证身份或匿名态，不保存或发布凭据明文。
- 功能脚本可以执行完成自身职责所必需的页面跳转，但入口页面、允许的页面转换和最终页面状态必须显式声明。
- 系统内权威资产是结构化语义脚本，不是任意 TypeScript、`.spec.ts` 或可执行 JavaScript 文件。

## 2. 首期结构

每个功能脚本至少表达以下逻辑信息；字段、动作、断言与引用的机器可校验格式已由 `semantic-script-schema.md` 锁定，数据库修订结构另见目标数据模型：

| 组成     | 语义                                                         |
| -------- | ------------------------------------------------------------ |
| 身份     | 业务版本、功能模块、脚本稳定标识、名称、业务目的和精确修订号 |
| 页面范围 | 入口页面锚点、允许的页面转换和成功后的页面状态               |
| 输入定义 | 输入名称、类型、是否必填、是否敏感、默认值和说明             |
| 前置条件 | 页面身份、登录状态、业务数据状态和其他只检查不补做的条件     |
| 有序步骤 | 稳定步骤标识、业务意图、动作、目标描述、参数引用和步骤后检查 |
| 最终断言 | 判断功能脚本成功的业务结果，不允许修复过程自动削弱           |
| 输出定义 | 输出名称、类型、提取方式、敏感性和发布条件                   |
| 副作用   | 影响类型、业务资源、资源身份、确认方式和重试约束             |
| 恢复信息 | 已确认检查点、已执行步骤、页面状态和副作用状态               |

每次运行必须绑定精确脚本修订，不能只记录一个会随修复变化的脚本标识。稳定实体、不可变 revision、current 激活与内容 hash 规则见 `target-data-model.md`。

## 3. 输入与变量绑定

- 功能脚本只能读取已声明输入，不得按名称隐式读取全部全局运行变量。
- 场景调用负责把固定值、版本配置、主代理授权的运行变量或密钥引用映射到脚本输入。
- 首期输入采用可验证的 JSON 值类型；枚举、对象和数组必须带约束，不能使用含义不明的自由结构。
- 密码、Token 等敏感输入只保存引用，不把真实值写入业务版本、脚本、日志、截图说明或普通运行变量。
- 输入校验在任何浏览器副作用发生前完成；缺少或不合法输入时脚本不开始执行。

## 4. 前置条件

前置条件是检查契约，不是隐式修复逻辑：

- 页面身份和路由符合脚本声明。
- 登录状态、账号角色或权限符合要求。
- 所需业务数据存在或不存在。
- 页面关键区域已经可交互。

前置条件不满足时，子代理保存现场并上报阻塞或可恢复中断。登录、补充测试数据、跳转到场景外页面等动作由主代理重新编排；子代理不得擅自扩大脚本职责。

## 5. 步骤与控制流

- 首期功能脚本使用有序、线性的语义步骤，不支持通用条件分支、业务循环或嵌套脚本调用。
- 重复创建、批量准备数据、条件分支和跨脚本依赖属于场景调用图，由主代理执行。
- 等待、同一步骤内的有限重试和目标重新解析属于技术执行策略，不算业务循环；必须有明确上限。
- 每个浏览器动作执行前重新解析目标，执行后立即检查预期页面变化，并记录可关联的步骤结果。
- 目标定义保存业务语义和可序列化定位依据；`Page`、`Locator`、`ElementHandle` 等 Playwright 进程内对象不进入脚本或跨服务传输。
- 任意 JavaScript / `dom_script` 不作为首期功能脚本的业务动作。必要的只读诊断只能使用已登记、Schema 受限的 observation 并保存证据，不能执行任意脚本，也不能绕过可视语义执行链改变页面或业务状态。

首期动作白名单、断言算子、目标引用结构及浏览器能力差距见 `semantic-script-schema.md`；缺失动作不得临时映射为 `dom_script`。

## 6. 断言

断言分为三层：

1. 执行前的前置条件检查。
2. 每个动作后的局部变化检查。
3. 脚本完成时的业务结果断言。

首期不使用会被忽略的“软断言”。不影响成败的采集项定义为观察信息；用于验收的断言失败必须使当前脚本失败。AI 可以修复定位和交互方式，但不得删除、弱化或改写业务断言来制造通过。

## 7. 输出发布

- 输出必须预先声明，并能关联到产生它的步骤和证据。
- 执行期间提取的值先进入当前脚本调用的暂存区；脚本全部业务断言通过后，才按声明发布到主代理维护的运行上下文。
- 脚本失败、中断或等待决策时，部分输出默认不提供给下游任务，只作为未确认数据写入证据包。
- 主代理在重新检查页面和副作用后，可以显式确认部分输出并用于恢复或清理，但不能把未确认输出自动当作成功结果。
- 敏感输出只发布受控引用，证据和普通变量中必须脱敏。

## 8. 副作用与重试

功能脚本必须声明其业务副作用，至少区分：无业务写入、创建、更新、删除和认证会话变化。对于有副作用的步骤，还必须声明受影响资源、可验证身份、有限影响数量、可逆性和应用检查；上传或可能提交表单的动作不能用“无副作用”绕过声明。

默认重试规则：

- 无业务写入的操作可以在限定次数内安全重试。
- 创建、更新、删除和认证变化在重试前必须先检查副作用是否已经发生。
- 认证变化脚本只有在身份/角色或匿名态硬断言通过后才允许主代理更新活动 actor；失败或中断时认证状态视为未知，不能假定仍是原身份或已切换成功。
- 超时、连接中断或工具调用失败不能证明浏览器动作没有生效；副作用未知时不得盲目重放。
- 副作用已发生但最终断言失败时，结果仍不是通过；子代理上报实际状态，由主代理决定确认输出、执行补偿、重新派发或暂停决策。

清理或补偿本身应由独立功能脚本表达并由场景编排，不能在原脚本失败后偷偷执行。

环境策略固定为：local/test 自动执行已声明且有界的副作用；staging 对删除、批量、不可逆和上传在计划开始前做一次用户审批；production 只允许显式认证会话变化和只读行为，业务写入/上传硬拒绝。完整风险投影与 grant 契约见 `environment-side-effect-policy-contract.md`。

## 9. 调用结果

一次功能脚本调用至少返回：

- 绑定的业务版本、场景调用、功能脚本和精确修订标识。
- 执行结果及未通过原因。
- 已执行步骤、最后确认检查点和当前页面状态。
- 已确认输出、未确认部分输出和脱敏后的输入摘要。
- 副作用状态及其验证证据。
- 对后续任务的阻碍判断和建议恢复条件。
- 截图、DOM、操作记录等证据引用。

结果状态 token 遵循 `run-state-decision-evidence-contract.md`；传输信封由跨服务 API 契约统一定义。

## 10. 编排示例

“批量删除用户”场景可以先多次调用“新增用户”功能脚本，每次传入不同输入，并把成功输出的用户标识写入运行上下文；随后再调用“批量删除用户”脚本消费这些标识。

“新增用户”脚本本身只负责新增及验证，不包含循环，不调用删除脚本，也不在失败后自行登录或清理。若提交动作超时，子代理先检查目标用户是否已经创建，再由主代理决定确认输出、重派或调用独立清理脚本。

## 11. 当前实现

- 功能脚本是功能模块下的稳定身份，current revision 保存结构化语义步骤和副作用声明。
- 场景通过调用 DAG 组合功能脚本，并由共享浏览器会话可视执行；不支持任意 TypeScript/JavaScript 脚本执行。
- Run 冻结输入、输出、断言、副作用和 revision，执行尝试记录检查点、影响与证据。
- valid/current 脚本写入与 AI candidate 标记为 valid 前统一经过 `FunctionalScriptV1Schema` 和静态引用 validator；运行前继续校验 DAG、冻结投影、scope verification 与权限交集。
