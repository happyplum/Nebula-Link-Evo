# 业务版本与页面资产契约

> 状态：`pending`。本文定义已经确认的目标语义；当前 ai-e2e 只有 project、完整 URL、URL↔模块绑定和单份页面快照，尚无业务版本、逻辑页面、参数 Schema 或独立复制模型。

## 1. 目标层级

目标资产层级为：

```text
项目
└─ 业务版本
   ├─ PRD、解析结果与决策记录
   ├─ 部署/Git 元数据与默认部署引用
   ├─ 页面定义
   │  ├─ 功能模块
   │  │  └─ 功能脚本
   │  └─ 页面基线变体
   └─ 测试场景与 TODO 模板
```

项目表示长期产品或系统；业务版本表示一套可以独立生成、修改、验证、复制和运行的 E2E 资产。运行计划、执行尝试、实际数据和证据不属于业务版本资产。

## 2. 业务版本

业务版本至少记录稳定标识、用户可读名称、来源版本、可选部署标识、可选 Git 标识、创建时间和当前校验状态。

- 业务版本是可编辑工作区；每次运行通过冻结运行计划保证执行不受后续编辑影响，不要求为了运行锁死整个版本。
- 版本资产发生修改后，原有“已校验”结果失效，必须重新完成结构校验和必要的页面检查才能作为标准运行输入。
- 版本状态使用 `draft/validating/needs_recheck/valid/invalid/archived`；归档版本只读，但仍可查看、运行历史快照、复制或导出。删除与保留规则见 `target-data-model.md`。
- `sourceVersionId` 只用于来源追溯，不形成任何可变共享关系。
- 部署和 Git 信息是版本/运行元数据，不参与页面、模块或脚本的逻辑身份。

## 3. 版本复制

`copy` 是一次原子深复制操作：

- 复制 PRD、解析结果、决策记录、页面定义、模块、功能脚本的当前有效修订、场景、TODO 模板、变量定义、DOM/定位基线和参考截图。
- 为目标版本及全部资产生成新身份，并在复制事务内重建页面→模块→脚本→场景调用等内部引用。
- 目标资产可以记录来源资产和来源修订用于审计，但不能继续读取或写入来源版本的可变内容。
- 复制的是当前有效资产快照，不复制来源版本的编辑事件历史、运行计划、运行 TODO、执行尝试、失败证据或实际测试数据。
- 不复制 Cookie、登录状态、Token、密码、密钥值或临时运行变量；只允许复制不含秘密的配置结构和密钥引用定义。
- 复制失败或引用校验不通过时整体回滚，不产生半成品版本。

新版本可以选择新的部署/Git 标识。被复制的 DOM、定位和截图只是初始参考，每次运行仍必须重新检查当前页面。

## 4. 部署配置

部署配置与逻辑页面分离，至少包含基础 Origin/Base URL、允许访问的 Origin、环境标签和可选 Git/构建标识；认证信息只保存密钥引用。

- 业务版本可以指定默认部署引用，启动运行时必须冻结实际使用的部署配置和 Git/构建标识。
- 同一套页面、模块、脚本和场景资产可以在明确选择的兼容部署上运行，不因主机名或端口变化复制整套页面资产。
- 跳转到未授权 Origin 时停止当前任务并上报，不由子代理自行扩大访问范围。

项目支持多套命名部署 profile，每次业务版本绑定和运行都引用精确 immutable deployment revision；环境风险审批属于待确认安全策略，不影响“部署地址不属于页面逻辑身份”的原则。

## 5. 页面定义与页面锚点

页面定义表示稳定的逻辑页面；页面锚点表示某次调用中带具体参数的页面目标。

页面定义至少包含：

- 业务版本内稳定页面标识和用户可读名称。
- 路由模式：普通 path route 或 SPA hash route。
- 不含 Origin 的规范化路由模板。
- path、query 和必要 fragment 参数的名称、类型、必填性、约束与身份分类。
- 页面识别条件、认证要求、允许的页面转换和所属功能模块。

页面锚点至少由“页面定义 + 部署引用 + 已校验参数绑定”组成，运行时解析为实际 URL。实际 URL 是运行结果和证据，不作为资产主键。

一个功能模块只归属一个主要页面定义；一个页面可以包含多个功能模块。功能脚本声明入口页面锚点和允许转换到的页面定义，不通过跨页面绑定扩大模块职责。

## 6. 参数分类

URL 参数按对页面身份的影响分为三类：

| 分类     | 示例                                        | 处理方式                                                        |
| -------- | ------------------------------------------- | --------------------------------------------------------------- |
| 身份参数 | `tab=permissions`、`mode=edit`              | 固定值或受控枚举进入页面定义签名                                |
| 运行参数 | `/users/:userId`、`page=2`、`keyword=alice` | 页面定义只保存参数 Schema，实际值保存在页面锚点和脱敏运行证据中 |
| 忽略参数 | `utm_source`、临时追踪 ID、缓存戳           | 不参与页面匹配；可按策略从证据中保留或脱敏                      |

同一路由中只有业务含义稳定、会改变页面功能集合或验收语义的参数才应升级为身份参数。搜索词、分页、排序、临时资源 ID 和跟踪参数默认不是页面身份。

## 7. 规范化与匹配

首期页面签名由“路由模式 + 规范化路由模板 + 身份参数约束”组成：

- Origin、协议、主机和端口由部署配置提供，不进入页面签名。
- 使用标准 URL 解析规则处理相对路径、`.`/`..`、重复分隔和编码；根路径外的尾斜杠采用项目内一致策略。
- path 默认保留大小写语义，不擅自转小写。
- query 键按稳定顺序处理；运行参数值和忽略参数不进入页面签名。
- SPA 的 `#/route` 作为 hash route 解析；普通页面片段默认不参与身份，除非被显式声明为身份参数。
- 首期支持静态段和有约束的命名参数，不使用无法可靠消歧的任意通配页面。

页面匹配优先选择静态路由，再选择约束更具体的参数模板。若同一实际 URL 能匹配多个同等优先级页面，业务版本校验失败，必须在运行前合并、拆分或补充约束。

例如：

```text
部署 Base URL: https://staging.example.com
页面定义: /users/:userId
身份参数: tab=profile
运行参数: userId=42, page=2
忽略参数: utm_source=e2e
实际 URL: https://staging.example.com/users/42?tab=profile&page=2&utm_source=e2e
```

该实际 URL 仍属于 `/users/:userId + tab=profile` 页面定义，不会因为 `userId`、分页或追踪参数变化创建新页面。

## 8. 页面状态与组件边界

- 弹窗、抽屉、下拉菜单和没有稳定导航身份的局部状态不是独立页面，归所属页面的功能模块和脚本步骤管理。
- 不改变 URL 但会长期改变功能集合的 Tab/模式，优先作为页面状态；只有它能够稳定深链、独立承载模块和验收语义时才成为身份参数或独立页面定义。
- 登录页、错误页和无权限页是可识别页面状态；意外跳转到这些页面时按中断或阻塞处理，不能误匹配为原业务页面。
- 新 Tab 仍使用页面定义和页面锚点识别；Tab 身份是运行时浏览器信息，不进入业务版本资产身份。

## 9. 页面基线变体

一个页面定义可以保存多个命名基线变体，用于表达确有意义的稳定状态，例如空列表、有数据列表或不同角色视图。每个基线变体至少记录：

- 页面定义、状态名称和适用前置条件。
- 角色、Locale、视口类别及会影响 DOM 的已知配置摘要。
- 捕获时解析后的 URL、部署/Git 标识和时间。
- DOM 快照、页面状态摘要、参考截图、目标定位提示和内容指纹。

基线不是运行真相：

- 每次运行先获取当前 URL、DOM 和截图，再选择最匹配的参考变体。
- 定位器和 DOM 节点引用只是提示，动作前必须重新解析目标。
- 找不到匹配变体时可以继续探索或暂停决策，但不能把任意旧快照伪装成当前页面。
- 运行截图、失败 DOM 和操作记录属于运行证据，不直接覆盖版本基线。
- 只有脚本修复经过重新执行并通过后，才可以新增或更新当前业务版本的基线变体。

## 10. 页面发现与人工校正

- Explorer 收集的完整 URL 是“页面观察”，不是最终页面定义。
- 系统依据路由结构、参数变化、PRD 语义和 DOM 相似性提出页面归并、参数分类及模块绑定建议。
- 置信度不足、路由模板冲突或多个参数可能影响业务语义时，在版本进入可运行状态前要求人工确认。
- 人工合并或拆分页面后，必须重新映射模块、功能脚本、场景调用和基线引用，并通过完整引用校验。

## 11. 运行时页面校验

每个页面任务和功能脚本开始前至少检查：

1. 当前 Origin 是否属于冻结部署的允许范围。
2. 当前 URL 是否唯一匹配预期页面定义。
3. path/query/fragment 参数是否符合 Schema 和当前调用绑定。
4. 当前页面是否为登录、错误、无权限或其他异常页面。
5. 当前 DOM/截图是否能匹配声明的基线变体或满足脚本前置条件。

检查结果、实际参数和匹配的基线变体写入执行尝试；敏感参数必须脱敏。

## 12. 当前实现差距

- 当前 `projects.target_base_url` 同时承担项目和部署地址，没有业务版本或运行时部署快照。
- 当前 `urls` 保存完整 URL、单份 `page_snapshot_json` 和项目归属，没有逻辑页面、路由模板、参数 Schema、基线变体或版本归属。
- 当前 `url_module_bindings` 直接把完整 URL 记录绑定到功能模块，无法稳定复用动态参数页面或跨部署资产。
- 当前手工添加 URL 只用 `new URL(record.url).pathname` 生成展示 path；Explorer 只做同源检查和 URL 解析，没有规范页面签名或歧义检测。
- 当前没有业务版本 copy、独立资产身份重映射、来源追溯或复制事务。

## 13. 技术落点与剩余实现细节

- `target-data-model.md` 已锁定稳定实体 + 不可变修订表、唯一 current、版本 copy 事务、多命名部署 revision、页面模板语法、参数类型、WHATWG URL 规范化、消歧评分、基线指纹/阈值与内容寻址存储。
- 部署环境的数据风险审批规则仍需用户确认；秘密只以 provider reference 保存。
- 旧 project/URL/binding/snapshot 数据的分批迁移、兼容读写和回滚步骤在迁移契约中单独定义。
